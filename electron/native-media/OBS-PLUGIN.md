# Roomcast encoded OBS bridge

`runtime/native-media/roomcast-native.dll` is a GPL-2.0-or-later OBS 32.1.2 plugin built from this directory's C source. It uses the bundled OBS GPU scene and encoders, then emits encoded H.264 Annex-B through the authenticated local obs-websocket connection. It has no independent encoder runtime. Build with a MinGW-w64 UCRT compiler using `build-obs-plugin.ps1`; the fixed OBS headers come from the existing `runtime/obs-source/OBS-Studio-32.1.2-Sources.tar.gz` archive. Build caches remain under runtime. Do not load this ABI-specific plugin into an unrelated OBS version. GPL text is retained in `GPL-2.0.txt`; the separate plugin does not change the license of other Roomcast source files.

Vendor `roomcast-native` exposes `start`, `stop`, `bitrate`, `keyframe`, and `status`. Every request carries a unique `session`; start/bitrate also carry `bitrateKbps` (300–6500). A stopped session must never be reused. `Frame` events contain session, Annex-B `data` (base64, SPS/PPS prepended to IDR), keyframe, ptsUs, dtsUs, epochUs and bytes. Epoch timestamps map OBS monotonic frame time to UTC for alignment with separately encoded audio.

Start attempts `obs_nvenc_h264_tex`, then `obs_x264`. Both use High profile, CBR, no B frames, no lookahead, a one-frame initial VBV and one-second IDR interval. NVENC uses p3/ull, x264 uses veryfast/zerolatency. Actual chosen encoder and initialized settings are returned; initialization failures return `ok=false`. Browser offers must support H.264 High or use the existing media fallback. NVENC's own OBS implementation retains at least three frames of output pipeline delay; single-frame VBV is not a zero-delay promise.

The NVENC keyframe request uses official `obs_encoder_update` behavior: the bundled NVENC implementation requests `resetEncoder` and `forceIDR`. Requests within 300 ms are coalesced. x264 reports the next periodic IDR instead of claiming an immediate request. Dynamic bitrate updates retain the initial VBV size, so the response reports vbvBits explicitly; the buffer duration grows if bitrate decreases. `obs_encoder_update` is asynchronous, so a request acknowledgement is not hardware readback.

No raw pixels or microphone content pass through this plugin. OBS scene selection and audio handling stay with their existing owners. A session nonce prevents late frame/control traffic from affecting another sharing session; retired session IDs are retained for the last 64 stops.

Official sources: OBS 32.1.2 `libobs/obs-output.h`, `libobs/obs-encoder.c`, `plugins/obs-websocket/lib/obs-websocket-api.h`, `plugins/obs-nvenc/nvenc.c`, `nvenc-opts-parser.c`, and `plugins/obs-x264/obs-x264.c`, all in the retained source archive and [OBS's official repository](https://github.com/obsproject/obs-studio/tree/32.1.2).
