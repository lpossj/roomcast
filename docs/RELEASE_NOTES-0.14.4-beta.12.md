# Roomcast 0.14.4-beta.12 本地交付与人工验收

此版本以校园网用户为主要对象，接续本地 beta.11；保留 EasyTier、普通 WebRTC 优先、现有 VDO/公网 TURN 回退，以及 OBS、原生采集、系统声音、语音和网页功能。没有 push、tag、Release 或部署。

## 本次校园媒体改动

1. **EasyTier 画质控制接线**：原 `campus` 路线和公网 TURN 一样只有编码负载保护，没有接入现有的网络分辨率升降策略。现在校园路线复用 `createP2pVideoPolicy`、基于采集源尺寸的缩放、原拥塞/恢复规则及 beta.11 的档位提交修复。该路线不再同时运行旧的一次性缩放校准，避免两个模块写入缩放参数。没有新造控制器、提高码率或更改阈值；公网 TURN 继续使用原观察分支。
2. **独立语音校园回退**：原房间和屏幕可用 EasyTier，但 `RoomVoice` 只创建普通 ICE 连接，且校园候选会被普通连接过滤，导致校园用户可能进房/看画面成功却语音不通。现普通语音失败后，在双方明确声明支持的情况下，由原 5 秒重试循环为该成员准备校园连接，复用 `prepareCampusConnection` 和同一房间会话。正常普通语音保持，不依赖开启屏幕共享。
3. **语音协商减少往返等待**：先派发 SDP，候选沿原有序信令通道跟随，不再逐个等 ACK 后发送下一个候选；候选队列逐项容错。信令确认、成员授权和麦克风状态仍有效。

语音新增字段仅允许出现在 offer/answer：`route` 限定 `p2p/campus`，`campusCapable` 必须为布尔值，校园路线必须声明能力。已有成员、麦克风、纯音频 SDP、候选方向和限流校验保留；没有新增端口、服务、管理接口或放宽 ACL。校园 ICE 使用原专用适配器，不混入公网 STUN。

语音复用现有初连 20 秒、已连接断线 8 秒宽限、校园总准备期限。校园初次失败只尝试一次，之后回到普通重试；普通路线恢复成功、重新开启该成员麦克风或重新入房后可再次尝试。已工作的校园语音中断允许恢复。取消、成员离开、关闭麦克风、离房都会移除相应连接；房间或画面仍持有校园连接时不停止它们的共享会话。

**兼容条件**：校园语音回退需要双方桌面端和主持房间的客户端均支持新语音能力字段。旧端/旧主持端未声明能力时仍用原语音路径；手机与网页浏览器不会因此获得内置 EasyTier。没有要求用户注册或配置新的后台。

## 同时包含的 beta.11 / beta.10 改动

- 修复 CPU 帧率限制与画质档位重叠时逻辑档位卡住；现在该修复也覆盖校园画面。
- 认证入房后后台加载聊天历史，历史超时不再退出房间；创建并行准备、预连接、空历史跳过和原阶段耗时记录保留。
- 屏幕 offer 派发后立即发送候选，仍检查 ACK 和清理取消/晚到会话。
- 普通房间、屏幕、语音默认增加腾讯/小米 STUN 候选，保留 Cloudflare；VDO 用固定 SDK 的 `stunServers` 参数。依据及旧配置恢复方法见 [beta.11 说明](RELEASE_NOTES-0.14.4-beta.11.md)。
- beta.10 的重连声音选择、语音断线收敛、VDO 凭据轮换不打断校园连接、近期解码耗时缓冲修复保留。

## 结果边界

未运行自动化测试、烟雾测试、验证脚本或实网探测，未添加/删除测试。源码接线和正常构建打包不能证明功能通过。

校园网实际成功率、首帧、画质恢复速度、听感及跨版本行为均待人工验收。不能断言这些源码缺口就是此前 300–600ms 或 360p 的现场根因。

尚缺同一失败会话的创建/播放阶段耗时、媒体 RTT、丢包、发送排队、实际 fps/分辨率，以及 EasyTier 底层直连/中转与协议信息。现有显示的“EasyTier虚拟网”不等于底层直连；控制延迟也不是视频端到端延迟。没有这些数据，不猜测调整节点、MTU或网络阈值。

PeerJS/VDO 信令域名和邀请传递继续现有配置。STUN 候选不能解决信令不可达，第三方公共资源没有永久可用保证。EasyTier 已有国内 STUN、UDP 优先及原 TCP 后备保留；没有改 Worker、公网 TURN、凭据取得或启用规则，没有改系统代理/DNS/默认路由，没有新增中继不可用提示。

## 人工验收（五项）

1. **校园网入房与首帧**：两端及主持端都换用 beta.12，校园网与另一网络互连，创建/加入并观看，导出原阶段耗时；观察普通 WebRTC 优先、失败后 EasyTier 接续，以及取消后是否停止当前尝试。
2. **校园画质**：确认画面为 EasyTier 路线，原生和 OBS 分别分享文字/动态画面；人为制造带宽或编码负载再恢复，记录实际分辨率、fps、RTT、丢包与发送排队，和旧包对照是否能恢复清晰度且不反复升降。
3. **校园独立语音**：不共享画面也开启双方麦克风和成员声音；在普通语音无法连接的校园环境下观察回退后能否双向听到，随后短断网再恢复；关闭麦克风/离房后确认声音与对应连接结束。
4. **混合端与健康连接**：新旧桌面、电脑网页和手机网页混合入房，确认原语音/观看仍可用，浏览器不拉起校园组件；正常直连用户不被校园失败成员打断，原 VDO/公网 TURN 回退仍按原条件工作。
5. **声音与配置回归**：确认系统声音、重连声音选择和聊天历史；手动确认腾讯/小米/Cloudflare 候选的可达性与单项失败场景，必要时按 beta.11 说明恢复旧 STUN 配置。不要把线上旧版本当作本地 beta.12。
