# Roomcast 0.14.4-beta.6 Beta

Windows 10/11 x64。本版继续使用 WebRTC，调整画质、帧率与资源平衡；线上网页仍为 beta.2，本次未部署网页。

## 变更

- VDO 发布传入用户设置的码率上限和帧率请求，补齐有界画质诊断。
- 短时发送排队需要持续证据才触发降档，保留丢包、严重排队和持续拥塞保护。
- P2P/TURN 优先协商设备支持的 H.264 High，保留其他编码回退；VDO 使用 SDK 公开的 H264 选项。
- 1080p60 命名预设维持 6500Kbps。仅撤销本地 beta.5 的命名 16000Kbps 迁移，自定义及自动码率保留。
- 高于30FPS的分享，在连续3次CPU限制或每帧编码耗时达到帧预算80%时，按60/45/30逐级减少编码帧数；连续8次健康且至少10秒冷却后逐级恢复。高压缩程度、低实测帧率或带宽限制本身不触发CPU保护。
- P2P 合并既有发送参数更新；VDO 复用原统计轮询。编码负载保护不修改码率上限、分辨率、采集轨或连接路线；既有严重网络拥塞保护仍可降低分辨率。

OBS和原生采集保留。媒体仍为原生P2P优先、VDO direct备选、直连耗尽后TURN兜底；TURN取用方式不变。本机预览复用本机采集流。

## 验证与限制

- 274项完整发布回归通过，0失败或跳过；许可、构建和网络门禁通过。日常263项快速回归保留；实际VDO发布器和本机RTP发送器以模拟CPU信号验证60→45→60参数切换，保留6.5Mbps预算与连接。模拟信号不等于实际低配负载或公网画质收益。
- ZIP完整性、28个生产文件及六个ZIP关键文件对比通过；包内版本、欢迎页、桌面桥接与必要资源的隔离启动通过。便携EXE复用同代码已验收成品。运动测试使用本机受控观看链路，不能代表公网或其他显卡。
- 包内OBS 32.1.2启动、1280×720/60FPS设置、来源枚举、虚拟摄像头模块及便携资源预检通过。
- OBS与原生在6500Kbps预算下的运动画质、实际编码帧率仍有差异；固定45FPS、HEVC或软件VP9/AV1候选没有表现出可直接作为默认值的统一收益。动态模糊尚未确认解决。
