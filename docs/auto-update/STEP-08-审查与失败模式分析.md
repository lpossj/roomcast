# STEP-08 审查结论与失败模式发散分析

> 时间：创建于 2026-09-26 15:28（取自文件系统）；本步的完整时间线见 [TIMELINE-全程时间戳记录.md](TIMELINE-全程时间戳记录.md)。

- 目的：按"每做一步就审查"的要求，记录**独立审查**与**自查**发现的问题、处理结果，
  并对"还可能出什么问题"做发散分析（含是否接受、如何缓解）。
- 审查方式：① 每一步完成后回读改动并写审查结论（STEP-01~06 各自的最后一节）；
  ② 全部改完后请一个独立视角对整份改动做对抗式审查（只读、不改文件），逐条核对代码；
  ③ 对最高风险件（替换脚本）做真实执行验证（见 STEP-07 §3）。

## 一、独立审查发现的问题与处理

### 阻塞级

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| B1 | **便携版（默认发布形态）无法覆盖 EXE**。`process.pid` 是被解压出来的内层 `Roomcast.exe`；外层启动器才是持有下载 EXE 文件锁的进程（已核对 `app-builder-lib/templates/nsis/portable.nsi:86-90`：启动器 `ExecWait` 内层程序，之后才 `RMDir /r $INSTDIR`）。脚本等到内层退出就去覆盖，必然 Access denied → 更新失败且无提示 | **已修**：`buildApplyScript` 新增 `parentPid`，便携版额外等待启动器 PID（`process.ppid`，最多 120 次），并且复制改为最多 30 次重试；新增 2 项单测覆盖"等待启动器"和"无父 PID 时仍重试" |
| B2 | **弹窗右上角 ✕ 不"粘"**：effect 依赖里有 `modal`，开关一次设置面板就会再次弹出；手动检查更新后也会再弹 | **已修**：加 `promptedUpdateVersion` ref，同一版本每次运行最多弹一次；关闭后不再自动复现 |

### 主要级

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| M3 | 替换失败只写 `apply.log`，没有任何用户可见反馈；`robocopy` 非原子，可能半覆盖 | **部分修复**：新增失败标记文件（写在 `app.getPath('userData')`），主进程下次启动读一次并在界面提示"上次自动更新到 X 失败，当前仍是旧版本"+日志路径。**未做**：覆盖前备份 600MB 以支持回滚（代价过大，接受该风险并在此登记） |
| M4 | 更新流程绕过"迁移未完成不得强杀协调者"的既有约束：即使渲染层回了 `close-ready {ok:false}`，25 秒后照样退出 | **已修**：超时即**取消更新**（不修改任何安装文件），更新窗口提示"程序还没有退出（房间迁移可能未完成）"并提供重试 |
| M5 | 主窗口在下载/校验之前就关闭，之后若失败则没有主界面 | **设计取舍**（用户明确要求"点击更新后先把正在运行的程序关掉"）；**已加兜底**：更新窗口加载失败也会强制显示（`did-fail-load` + 3 秒兜底），失败提供"重试 / 打开发布页 / **关闭并重新打开程序**（`app.relaunch()`）"三条出路 |

### 次要 / 细节

| 编号 | 问题 | 处理 |
| --- | --- | --- |
| m6 | `find "<pid>"` 是子串匹配；`tasklist` 失败会被当成"程序已退出" | **已修**：改为 `tasklist /FI "PID eq N" /FO CSV` + `for /f` 精确取值；并加"`tasklist.exe` 不存在就直接放弃更新"的硬门槛（宁可更不了，也不覆盖正在运行的程序） |
| m7 | `startApplyScript` 没有 `error` 监听，spawn 失败会成为主进程未捕获事件 | **已修**：加 `onError` 回调，且 `pid === 0` 时抛错 → 不退出应用、界面提示、安装未被修改 |
| m8 | 流水线失败不清理工作目录（每次重试残留 200–600MB） | **已修**：失败时 `rm` 掉工作目录（此时尚未应用，删除绝对安全） |
| m9 | ZIP 中央目录长度未校验，损坏文件可能诱导超大 `Buffer.alloc` | **已修**：越界即报"文件可能已损坏" |
| m10 | 条目名未拒绝 NTFS 备用数据流（`a.txt:stream`） | **已修**：条目名含 `:` 一律拒绝 |
| m11 | 路径含 `!`/`%` 会被 cmd 展开，破坏脚本 | **已修**：`prepareUpdateInstall` 检测到即拒绝，并给出中文原因 |
| m12 | 死代码 | **已修**：删除未使用的 `preload.onUpdateState`、`readApplyLog`；`closing` 阶段现已真实使用；`extractZip` 的 `only` 由测试使用（保留） |
| m13 | 成功分支 `rmdir` 自己的工作目录 | **实测确认是真缺陷**（不止"通常失败"）：cmd.exe 边执行边读脚本，目录被删后解释器丢失后续行，**最后的重启步骤从未执行**。**已修**：脚本永不删自己的目录；只删 payload / 已用的新 EXE，日志与脚本保留，工作目录交给下次启动清理；单测加回归断言 |

## 二、自查（写完即回读）发现并修掉的问题

1. `update-check.mjs` 流式改造后返回值曾写成 `bytes: bytes.length`（此时 `bytes` 已是数字）→ 立即修正。
2. 更新弹窗可能与设置/共享弹窗叠加 → 有其它弹窗时让路，其它弹窗关闭后仍会弹出。
3. 关掉弹窗后又打开设置再关闭会重复弹出 → 用 `promptedUpdateVersion` 限制"每版本每次运行一次"。
4. 更新窗口若加载失败，主窗口已关，程序会"无界面存活" → `did-fail-load` + 3 秒兜底显示。
5. 便携版/目录版共用一条阶段文案，替换阶段实际还在等程序退出 → 新增 `closing` 阶段文案。
6. `waitForPid` 超时语义：给"等自己"和"等启动器"配了不同出口，避免等不到自己还硬覆盖。

## 三、发散：还可能出什么问题

| # | 场景 | 现状 / 缓解 | 是否接受 |
| --- | --- | --- | --- |
| 1 | 下载 220MB 中途断网 | 写 `.part`，失败删除，界面可重试；不影响已安装版本 | 接受 |
| 2 | 临时目录磁盘不足 | 明确提示"磁盘剩余空间不足…请清理临时目录后重试" | 接受 |
| 3 | 覆盖过程中断电 / 被强杀 | 可能半新半旧；**没有回滚**。缓解：重新运行更新会全量重覆盖；失败标记会提示 | 接受（回滚需备份 ~600MB） |
| 4 | 程序装在 `Program Files` 等无写权限位置 | `robocopy` 返回 ≥8 → 失败标记 + 下次启动提示；用户可换便携版或管理员运行 | 接受 |
| 5 | 更新期间又开一个实例 | 单实例锁（`requestSingleInstanceLock`）保证只有一个；脚本只等自己的 PID 与启动器 PID | 接受 |
| 6 | 用户手动删掉 `%TEMP%` 工作目录 | 脚本找不到文件 → 失败标记 → 下次启动提示 | 接受 |
| 7 | 便携 EXE 被移动/改名/所在目录只读 | 复制重试 30 次后失败 + 标记；`PORTABLE_EXECUTABLE_FILE` 始终指向真实路径 | 接受 |
| 8 | 杀软拦截覆写 exe | 同 7；用户需手动放行或手动下载 | 接受（未签名产物的固有代价） |
| 9 | 退出时 OBS 子进程仍占用 `resources` | `robocopy /R:2 /W:1` 重试；仍失败则失败标记 | 接受 |
| 10 | 用户更新中途关掉更新窗口 | 应用退出，安装目录**未修改**；临时目录下次启动清理 | 接受（等同于取消） |
| 11 | 覆盖不 purge，旧版本残留文件 | 有意为之：`/E` 不删，避免误删用户放进程序目录的东西 | 接受 |
| 12 | 未来发布只提供 NSIS 安装器 | `describeRelease` 只收集 `Windows.exe/zip`，`selectInstallAsset` 不会误装 `Setup.exe` | 已覆盖 |
| 13 | 发布页缺少 `SHA256.txt` | 硬规则：拒绝自动安装，只保留手动下载 | 已覆盖 |
| 14 | 下载内容被中间人篡改 | 需与发布页 SHA256 完全一致；发布页/账号本身被攻破无法防御（未签名），UI 与文档已如实说明 | 接受并披露 |
| 15 | 用户在更新时再点"立即更新" | 流水线互斥，返回"更新已经开始了" | 已覆盖 |
| 16 | 更新弹窗在共享屏幕时弹出 | 不影响共享，关掉即可；文本明确"不会自动替换正在运行的程序"已改为真实流程说明 | 接受 |
| 17 | 房间迁移失败（`close-ready ok:false`） | 25 秒后取消更新并提示，不破坏房主迁移 | 已覆盖 |
| 18 | 源码/开发方式运行 | 明确拒绝自动覆盖（绝不动 `node_modules`），只给手动下载 | 已覆盖 |
| 19 | 便携版启动器不是父进程（非常规启动方式） | 等启动器 120 次后进入复制重试 30 次；仍失败则失败标记 | 接受 |
| 20 | 用户从不重启应用 | 失败标记与临时目录长期留存（标记 < 200B，工作目录 >10 分钟后下次启动清） | 接受 |

## 四、结论

- 独立审查的 2 个阻塞项、3 个主要项、8 个次要项已全部处理（M3/M5 为部分处理并登记残余风险）。
- 真实执行替换脚本又抓出 1 个静态审查看不出的功能缺陷（m13），已修正并加回归断言。
- 残余风险集中在"覆盖阶段"本身（断电、无写权限、杀软、未签名来源），
  都已通过"失败标记 + 下次启动提示 + 手动下载兜底"给出可见反馈，不再静默失败。
