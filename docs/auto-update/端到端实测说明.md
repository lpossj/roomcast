## 一、为什么需要一个"旧版本"包

自动更新只在"当前版本低于发布页最新版本"时才触发。仓库源码版本是 `0.14.3-beta.2`（= 最新），
所以要么等下一个版本发布，要么**本地打一个版本号更低的包**（`0.14.3-beta.1`）来触发真实更新。
下面的命令就是做这件事。

## 二、重建 beta.1 测试包（目录版，约 1–2 分钟）

```powershell
cd C:\Users\Administrator\Documents\Deepseek\roomcast-source

# 1) 临时降版本号并构建渲染层
$pkg = Get-Content package.json -Raw
Set-Content package.json -Value $pkg.Replace('"version": "0.14.3-beta.2"','"version": "0.14.3-beta.1"') -NoNewline
node node_modules/vite/bin/vite.js build

# 2) 打包成"目录版"（不是便携单文件 EXE，这样才走 ZIP + robocopy 覆盖目录那条路径）
node node_modules/electron-builder/out/cli/cli.js --win --dir --publish never `
  --config.directories.output="C:\Users\Administrator\Documents\Deepseek\roomcast-update-test\eb-out"
Move-Item "C:\Users\Administrator\Documents\Deepseek\roomcast-update-test\eb-out\win-unpacked" `
          "C:\Users\Administrator\Documents\Deepseek\roomcast-update-test\Roomcast-Test-0.14.3-beta.1"
Remove-Item "C:\Users\Administrator\Documents\Deepseek\roomcast-update-test\eb-out" -Recurse -Force

# 3) 还原版本号并重建 dist（重要：否则仓库 dist 会停留在 beta.1）
$pkg2 = Get-Content package.json -Raw
Set-Content package.json -Value $pkg2.Replace('"version": "0.14.3-beta.1"','"version": "0.14.3-beta.2"') -NoNewline
node node_modules/vite/bin/vite.js build
```

> 注意：`--dir` 产物的 `resources/app.asar` 里 `package.json` 的版本号决定"当前版本"，
> 而 asar 完整性哈希由 electron-builder 写进 exe，所以**不能手工替换 asar**。

## 三、跑端到端检查（一条命令，自动跑完全流程）

```powershell
cd C:\Users\Administrator\Documents\Deepseek\roomcast-source
npm run check:auto-update -- --install "C:\Users\Administrator\Documents\Deepseek\roomcast-update-test\Roomcast-Test-0.14.3-beta.1"
```

脚本会：把安装目录**复制**到 `roomcast-update-test\runs\<时间戳>\install`（模板永不被改动）→
测试模式启动（窗口隐藏、独立数据目录）→ 通过 CDP 调真实的
`checkForUpdates()` / `updateTarget()` / `startAutomaticUpdate()` → 跟踪进度阶段 →
等旧进程退出 → 校验副本里的 `app.asar` 真的变成新版本 → 等程序自动重启 → 清理现场。

**期望输出（通过）：**

```
[auto-update] 检查更新： {"available":true,"version":"0.14.3-beta.2",...}
[auto-update] 安装目标： {"kind":"directory","supported":true,"reason":""}
[auto-update] 阶段：downloading 0%
[auto-update] 阶段：extracting 3/2010
[auto-update] 阶段：closing
[auto-update] 阶段：restarting
[auto-update] 安装目录当前版本：0.14.3-beta.2（期望 0.14.3-beta.2）
[auto-update] 程序已自动重新打开（副本目录内有 N 个进程）
[auto-update] 通过：0.14.3-beta.1 → 0.14.3-beta.2（下载 → SHA256 校验 → 解压 → 退出 → 覆盖 → 自动重启）
```

**失败时会自动打印**：`%TEMP%\roomcast-update-*` 的内容、`apply.log` 全文，
以及"有没有 apply.log"（没有 = 替换脚本没真正执行），并保留运行现场（`--keep` 也可强制保留）。

## 四、更轻的检查：只验替换脚本本身

```powershell
npm run check:update-apply
```

不联网、不下载：生成真实 `apply.cmd`，在丢弃式假安装目录上执行，验证
"等 PID → robocopy 覆盖 → 重启 → 清理 payload、保留日志"，并断言**不删除**目标目录里多余的文件。

## 五、怎么看"某个 app.asar 里到底是什么版本"

（原先放在 `_analysis` 的小工具已随工作区清理删除，这里用一行命令代替）

```powershell
node -e "const a=require('@electron/asar');const p=process.argv[1];console.log('version =',JSON.parse(a.extractFile(p,'package.json').toString('utf8')).version, '| 含自动更新 =', a.extractFile(p,'electron/main.cjs').toString('utf8').includes('roomcast:update-start'))" "C:\path\to\resources\app.asar"
```

> 若这一步读到 `Unexpected token ... is not valid JSON`：说明**该文件正在被替换**，
> 或同一进程此前读过旧归档（`@electron/asar` 按路径缓存头部，需先 `a.uncache(p)`）。

## 六、测试包的清理

`roomcast-update-test\` 整个目录都可以随时删除（包含 `runs\` 现场）。
要重新验证时，按第二节重建即可。仓库内的代码、文档、测试**不依赖**这个目录。
