# Roomcast 0.14.5-beta.2

OBS 桌面共享增加随包内置的原生低延迟媒体发送。适用于普通 P2P、最高 1080p60、300–6500 Kbps 的既有共享配置；更大自定义配置、浏览器采集、TURN、校园备用及 VDO 保持原路径。接收端仍为标准浏览器 WebRTC，不要求安装插件。

## 职责与生命周期

- OBS 负责选定来源、GPU 画面和 H.264 编码；优先现有 NVENC，CBR、关闭前瞻与 B 帧，初始 VBV 为码率除以帧率。不可用时尝试已有 x264；编码或格式能力不满足则回到原媒体路径。
- 内置小型发送进程复用 OBS 已带的 libdatachannel，每位观看者拥有独立 ICE/DTLS-SRTP 连接、SR/NACK/PLI；已有鉴权与屏幕信令负责协商。现有混合音轨由 Electron 编码成 Opus，音视频时间戳统一为 epoch 微秒。
- 一次共享编码一次，按观看者扇出；不再根据静态低流量下的 REMB 压低所有观看者的编码预算。原生路径保持用户预算，连续三个新视频 RR 报告约 10% 以上丢包时，仅该观看者转回原有拥塞自适应路径，本次共享不反复尝试该原生连接。
- 本地压缩帧管道背压有上限；丢弃依赖帧后等待关键帧恢复，不随意把缺引用的 P 帧继续发送。共享结束、退出、取消、编码器退出及迟到回调均按会话回收。
- 本地 DLL 限定固定随包 ABI 摘要；OBS 使用私有便携目录，清除额外插件路径环境变量。无需新增驱动或独立安装运行库。安全软件是否提示仍由其策略与签名信任决定。

## 本轮证据与验收

已完成官方实现对照、源码与生命周期审查、编译，以及分段的真实编码和双浏览器 H.264/Opus 接收检查。OBS 分段确认 NVENC 1080p60、6500 Kbps、108333 bit VBV、关键帧请求及停止清理；关闭一个观看者后另一观看者继续接收。

用户要求自行验收实际效果，后续不再扩展功能/性能实验。本轮没有完成新原生路径的端到端静止 30 秒恢复运动验收，不宣称约 490 毫秒尾部延迟或运动模糊已消除。分段可运行不等于整体体验已验收。

原生发送不包含完整 Chromium 拥塞控制；弱网由上述逐观看者回退交还既有路径。High H.264 协商不兼容的浏览器也回退。x264 的立即关键帧请求依靠最长约一秒的周期 IDR；NVENC 使用受节流的重配置请求。

新增组件源码、构建说明和许可证位于 `electron/native-media/`，随对应源码 ZIP 提供。复用 OBS、EasyTier 与系统驱动，不增加大型运行时，不提高原有码率上限。实际网页部署结果与 Windows 归档信息另见交付目录 BUILD-INFO。
