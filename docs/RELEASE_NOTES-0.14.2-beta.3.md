# Roomcast 0.14.2-beta.3

> 说明：本版未单独发布，与 beta.4、beta.5、beta.6 一起并入 `0.14.2-beta.7` 发布。下面"无成本跨端方案"第 1 步的手动上传 `WebViewer.zip` 流程已在 beta.4 被桌面端自动创建的内置网页入口取代，不再适用；其余变更（小窗置顶开关、浏览器入房不依赖 `/api/config`、自建信令随邀请传递）仍然有效。

## 本版变更

- 共享小窗默认不置顶。小窗控制栏新增“置顶小窗／取消置顶”；开启时使用 Electron 的最低 `floating` 置顶级别，关闭时恢复普通窗口。
- P2P 邀请页支持填写一个 HTTPS 网页入口，生成电脑或手机浏览器可打开的观看链接。房间密钥放在 URL 片段中，不随静态页面请求发送给站点。
- 浏览器加入 P2P 房间时不再依赖本机 `/api/config`。桌面浏览器在支持 `getDisplayMedia` 时可按现有房间权限分享；手机浏览器主要用于观看。
- 自建 HTTPS PeerJS 信令地址随邀请传给网页观看者；未配置时沿用 Roomcast 原有公共信令。

## 无成本跨端方案

Piik 的关键做法是用同一套浏览器界面连接房间，电脑端按能力选择浏览器采集或原生采集，手机端通过浏览器观看；控制和媒体分离，媒体优先 P2P。Roomcast 已有浏览器界面、P2P 信令和 WebRTC 媒体，因此本版只补齐网页邀请与浏览器入房，不迁移 Piik 的 Go 服务、SFU 或原生采集栈。

1. 将 `Roomcast-0.14.2-beta.3-WebViewer.zip` 上传到免费静态 HTTPS 托管服务，例如 Cloudflare Pages 的 Direct Upload，得到 `https://...pages.dev/` 地址。
2. 在 Roomcast 桌面端创建 P2P 房间，打开“分享房间”，将该地址填入“网页观看入口（HTTPS）”，复制电脑／手机网页观看链接。
3. 观看者用电脑或手机浏览器打开链接，填写昵称后加入，点击进入共享画面。桌面浏览器只有在支持屏幕采集且获得房间分享权限时才能发起共享。

网页包仅提供前端。房主的桌面客户端须保持运行；PeerJS 公共信令、STUN 和 P2P 直连仍是现有依赖。受限网络中两端可能无法直连，若需要保证连接，仍需可用的 TURN 中继，这不属于“零成本保证可用”的范围。手机浏览器屏幕采集能力不统一，本版没有实现手机发起屏幕共享。第三方全屏窗口的层级由操作系统管理，`floating` 级别不保证压在所有全屏或无边框全屏窗口之下。

## 验证

- 前端构建通过。
- Electron 小窗专项聚焦检查通过：默认不置顶、开启、关闭。
- 原有完整小窗检查在进入小窗阶段前，因主播放器控件自动隐藏等待超时而停止；该检查未验证本版新增行为。
