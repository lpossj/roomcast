# Roomcast 0.14.2-beta.9

本版新增桌面端更新机制，并保留 Beta 期间"不静默替换程序"的安全边界。

## 新增：更新检查

- 桌面端启动后会向后端检查是否有新版本（默认开启，可在"设置 → 关于"关闭），发现新版本时在左侧设置按钮上显示提示点。
- 设置 → 关于 里新增"软件更新"：当前版本、自动检查开关、"检查更新"按钮、新版本号与更新说明摘要。
- 版本比较遵循语义化版本规则：预发布版本低于同号正式版（`0.14.2-beta.9 < 0.14.2`），并按数字段正确排序（`beta.2 < beta.10`）；**正式版用户不会被推送测试版**。草案（draft）与非语义化 tag（例如 `runtime-2026.09`）会被忽略。
- 下载：按发布页提供的 Windows 产物（便携版 EXE / ZIP）下载到系统下载目录，并用发布页的 `SHA256.txt` 校验；校验不通过时**不写入文件**。发布页没有提供校验值时仍可下载，但会明确标注"未校验"。
- 网络受限时的兜底：检查或下载超时会给出明确提示，并在"软件更新"里始终提供**"打开发布页（手动下载）"**按钮，直接在系统浏览器打开 GitHub Releases 页；该按钮不依赖一次成功的检查结果，因此即使 API 完全不可达也能手动下载。
- 下载完成后可"打开文件位置"。本版**不会**自动替换正在运行的程序——未签名产物自动执行是安全降级，而且便携版 EXE 在运行时无法自我替换。

## 安全与隐私边界

- 更新检查只请求 GitHub 公开发布接口获取版本与产物列表，不发送任何设备标识、房间信息或使用数据。
- 下载地址与校验地址由主进程持有（来自它自己那次检查的结果），渲染进程只能**按名称**选择产物，不能指定 URL。
- 请求使用 Chromium 网络栈发起，因此遵循 Windows 的代理与证书配置（本机 Node 自带 CA 会被 TLS 拦截挡住，Chromium 使用系统证书store 正常）。
- 只有下载目录中的文件允许"打开文件位置"。

## 验证

- 全量单元测试 **160/160** 通过（新增 6 个更新机制用例：版本比较、发布选择、校验值解析、限流与错误映射、下载校验、篡改拦截）。
- 对真实仓库实测：当前 `0.14.2-beta.1` → 正确提示 `0.14.2-beta.2` 并列出 EXE/ZIP 与校验文件；当前 `0.14.2-beta.2` → 不提示；`runtime-2026.09` 等非语义化 tag 被忽略。
- 打包后的便携版实测：设置 → 关于 → 检查更新走通 IPC 与网络链路，返回"已是最新版本"。

## 已知限制

- 当前构建未签名，更新包同样未签名；下载后仍需要用户手动替换，Windows 可能提示未知发布者。
- GitHub 未认证接口限流为每小时 60 次/IP；界面按需检查，不会轮询。
- 网页端不提供更新检查（页面由房主的应用提供，跟随房主版本）。

## 发布流程提醒

更新检查读取的是 GitHub Release 的 `prerelease` 标记与 tag 名。**正式版发布时不得再使用 `--prerelease`**，否则正式版用户永远收不到该版本；tag 必须保持 `v<semver>` 形式，产物名必须保持 `Roomcast-<version>-Windows.exe|zip`。
