# Roomcast 0.7.0 聊天重构

## 协议

- `room:state` 仅包含房间、成员、角色权限和共享流状态，不再携带聊天数组。
- `chat:message` 每次只广播一条新消息。普通消息和系统消息都经过此事件。
- `chat:history` 是带确认响应的分页事件。默认和最大页大小均为 50：
  - `{ limit: 50 }`：最近 50 条。
  - `{ beforeSeq, limit: 50 }`：加载该序号之前的一页。
  - `{ afterSeq, limit: 50 }`：补齐该序号之后的消息缺口。
- 每个房间从 `seq = 1` 开始连续递增。客户端按 `seq` 排序和去重，并在收到房间状态后检查新消息缺口。

## 数据生命周期

房主的 authoritative room server 在内存中最多保存 1000 条消息。房间最后一名成员退出或房主应用关闭后，消息随房间内存释放，不写入数据库。新成员只请求最近 50 条；聊天区域滚动到顶部时，每次再加载 50 条。

P2P 模式没有绕过房主服务：访客的 `chat:send` 和 `chat:history` 通过 PeerJS DataChannel 转发给房主本地 Socket.IO 服务，房主服务验证成员身份并生成序号；`chat:message` 再通过相同 DataChannel 转发给访客。

## 主要代码

- `server/rooms.mjs`：消息序号、1000 条内存上限、单条广播、双向游标分页；房间快照移除消息。
- `src/p2p.js`：转发 `chat:message`，允许 `chat:history` RPC。
- `src/useRoom.js`：独立消息状态、按序号合并去重、最近消息加载、旧消息分页、缺口补齐。
- `src/App.jsx`：渲染独立消息状态，滚动到顶部加载旧消息并维持滚动位置。
- `src/enhancements.css`：历史加载状态样式。
- `tests/rooms.test.mjs`：验证房间快照、实时事件、序号、分页和补漏。

该历史版本当时未改动视频采集、WebRTC/PeerJS ICE、TURN 与媒体桥实现；当前版本已改为原生采集 + WebRTC。
