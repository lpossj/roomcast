# Roomcast 0.14.3-beta.5

> 本版本**同号重发**（2026-09-26 17:5x 覆盖 beta.5 原有发布资产），额外带上"替换脚本被主程序退出连带终止"的修复。
> 更新机制、SHA256 校验标准、界面均无变化；已发布资产已由新构建覆盖，版本号不变。

## 修复

**更新到最后一步却没有替换成功（同号重发中修复）。** 上一版为了去掉更新期间弹出的命令行窗口，
把派生替换脚本的方式从"分离进程"改成了"仅隐藏窗口"；但"分离"同时也是让脚本活过主程序退出的唯一手段，
两者不能只靠派生选项同时满足 —— 结果是下载、校验、解压全部成功、程序也正常退出，
**替换脚本却被连带终止**（`apply.log` 只有一行 `update start`，程序目录未变，也没有残留进程），更新静默失败。

现在改成两级隐藏启动器：由一个**分离的隐藏 PowerShell** 去接力，它用
`Start-Process -WindowStyle Hidden` 派生真正的替换脚本后立即退出 ——
**既不产生任何窗口，脚本也能活过主程序退出**。若拿不到启动器进程号，则退回"分离的 cmd"路径，优先保证脚本一定能执行。

**接口被限流时仍能检查到新版本。** GitHub 未登录接口每小时每 IP 只有 60 次请求，
被限流后旧实现会改用固定站点上的 `version.json`；而固定站点已不再随版本发布，
所以它会停留在旧版本号 —— 实测 beta.4 发布后，运行 beta.3 的用户被限流时**检查不到这次更新**。

现在降级链改为：

1. 先读仓库的**发布订阅**（`releases.atom`）—— 与接口同源、含测试版、**完全不消耗接口额度**；
2. 只有在订阅也失败时，才退回固定站点的 `version.json`；
3. 两者都失败才把原始接口错误报给界面。

界面会如实标注当前用的是哪种来源（"已改用发布订阅检查" / "已改用固定站点版本清单"）。
下载与安装仍然必须通过发布页 `SHA256.txt` 校验，安全标准不变。

## 保持不变

- 自动更新流程：启动弹窗 → 关闭正在运行的程序 → 下载进度 → SHA256 校验 → 解压 → 覆盖 → 自动重启。
- 上一版修复的内容：更新期间不再弹出命令行窗口；软件更新面板只保留「打开发布页」作为手动下载入口。

## 已知限制（同号重发的代价）

版本号相同意味着**已经运行 beta.5 的机器不会看到这次更新**（同版本不触发更新）。
若你的程序已经是 beta.5，需要手动下载本次覆盖后的安装包替换；仍停留在 beta.4 或更早的机器可以照常自动更新到本版本。

## 边界

Windows 产物未签名；`SHA256` 只能证明文件与发布页一致。覆盖无回滚。程序装在无写权限目录时更新会失败并提示。
