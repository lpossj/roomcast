# Roomcast 0.14.5-beta.1

本轮基于完整0.14.4-beta.15产品源，保留此前桌面激光加载修复及普通WebRTC优先、EasyTier按需备用、TURN、Worker、OBS等功能。独立本地分支codex/roomcast-0.14.5-beta.1；无push、PR更新、tag或GitHub Release。

## 修改

- 删除全房激光笔开关及协议判断，仅保留对他人的成员权限：房主可管理管理员/成员，管理员只能管理普通成员。
- 激光开关启用时在预览、全屏、小窗显示蓝底白图标，小窗采用与预览相同的激光/全屏图形；置顶使用竖直图钉。
- 房主在线时将有大小上限的最新房间快照及每人独立恢复票据提前发给成员，不冻结房间；角色/权限/凭据变化优先同步。聊天与观看变化合并推送，闲置不轮询导出。
- 主动离房和X/Alt+F4保持立即本地退出，不等待候选响应。其他成员在房主数据连接结束后，按管理员优先、同角色按入房顺序错开接任；无法接任者跟随新协调器重连。
- 接任期间保留其余共享者的采集和已有媒体连接。旧协调器静默退场，避免逐个离房消息误拆其他共享。
- 版本同步为0.14.5-beta.1。

## 依据及边界

参考Photon PUN/Fusion的预复制快照与成员恢复机制，仅借鉴设计，不使用其SDK/云服务。复用PeerJS固定房号注册、Roomcast本机房间服务与原迁移票据，不新增依赖或服务。

- https://doc.photonengine.com/pun/current/gameplay/hostmigration
- https://doc.photonengine.com/fusion/v2/technical-samples/fusion-disconnect-reconnect
- https://github.com/peers/peerjs-server/blob/master/src/services/webSocketServer/index.ts
- https://peerjs.com/client/api/peer

状态保存在成员内存中，只能恢复已收到的最后状态。极短时间内刚加入/刚接任即退出、未送达的聊天或共享变化可能无法完整恢复。优先顺序用于错开尝试；优先候选网络不可用或浏览器冻结时，后续可用成员可以接任。固定房号只在同一PeerServer信令域内互斥，不等同于网络分区共识。旧主机恢复信令时若ID已被接管会退让。

应让参与接任的Windows和网页使用本版；旧客户端不支持后台快照。没有运行自动测试、烟雾、测试脚本或新客户端，构建/封装和线上版本信息仅证明产物与部署，不代表真机功能通过。

## 人工验收

1. A创建房间，B先加入、C后加入并设为管理员；保持B/C的一路共享被彼此观看。A点击离房，确认A立即回到入口、C接任，房间与B/C共享保留。
2. 无管理员时按入房顺序接任；接任后再次离房，确认下一代快照继续生效。
3. A直接X/Alt+F4关闭；也在管理员网络较差时执行，确认A关闭不等待交接，其余成员后台恢复或显示具体失败。成员在恢复期间也应能立即退房/关窗。
4. 确认全房开关消失，个人禁用权限仍按房主/管理员层级生效；预览/全屏/小窗激光开关开启蓝色、关闭恢复，图标一致、图钉竖直。
5. 继续核对实际共享显示器/窗口上的透明激光覆盖与鼠标穿透；本轮保留beta.15实现，没有新增其真机成功证据。
