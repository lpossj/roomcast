# Roomcast 0.14.2-beta.2 Release Notes

## 版本

- 版本号：0.14.2-beta.2
- 类型：公开测试版（Beta）/ 缺陷修复
- 平台：Windows 10/11 x64
- 签名状态：未签名；Windows SmartScreen 可能提示未知发布者
- 上游基线：0.14.2-beta.1

本版是 0.14.2-beta.1 的缺陷修复版，针对以下三个已上报问题：

1. 观看者第一次无法与房主建立 P2P 连接，第二次才能进入房间。
2. 偶发在刚打开"开启共享"或"修改共享"时出现 OBS 来源读取错误。
3. OBS 模式来源不显示 → 切到原生采集 → 再切回 OBS 后，来源看起来显示了，但仍不能开始共享并报错。

## 主要变化

### 首次入房的等待时间不再过早结束

- 房主侧把"等待数据通道 open"和"8 秒 HMAC 鉴权"拆成两个独立阶段：ICE 建立有自己的 25 秒上限，鉴权计时只在数据通道真正打开后才开始。此前的实现让 ICE 阶段消耗掉鉴权窗口，慢速 ICE 会导致房主在挑战尚未发出时就关闭连接。
- 观看者侧的等待上限改为"25 秒 ICE + 8 秒鉴权"，与房主侧完全对齐。此前的 25 秒上限短于房主最坏情况所需的 33 秒，观看者会在房主仍能完成鉴权时先放弃，表现为"第一次进不去、第二次才能进"。
- 鉴权完成前后都重新检查连接状态，避免关闭后仍然建立本地 socket。

### 房主不再丢弃首帧屏幕信令

- 房主处理屏幕 offer 时不再依赖缓存的 `room.members` / `room.streams` 快照。首次 offer 可能在房间状态缓存更新前到达，旧实现会静默丢弃它，导致观看者超时。
- 发送方身份与"房主当前是否有活跃共享"仍由本地房间服务强制校验，未降低授权要求。
- 共享是否存活改用实时的 `screenStream.active` 判断，而不是缓存快照。

### 采集来源卡片不再跨引擎残留

- 每次枚举前清空屏幕/窗口列表与已选 `sourceId`。原生采集和 OBS 使用的来源 ID 属于各自引擎，OBS 枚举失败时不会再显示原生卡片或上一次的旧 OBS 卡片，也不会为不存在的来源提交共享。

### OBS 临时枚举源清理

- OBS 的 `RemoveInput` 只把来源标记为 removed，场景引用要等到 OBS 渲染该场景时才会被摘除，而最小化的 OBS 可能长时间不渲染。临时枚举源因此会继续出现在 `GetInputList` 中，导致"OBS 临时枚举源无法清理"偶发失败。
- 清理改为先显式 `RemoveSceneItem` 摘除场景项、再 `RemoveInput`，并把 OBS 已确认移除的名字排除在后续枚举之外，使清理判断不再受 OBS 对象延迟销毁影响。
- 真正未被移除的枚举源仍会阻止下一次枚举，不会为了"跑通"而忽略失败。

### OBS 首次准备与便携版隔离

- 准备内置 OBS 时先在独立的 staging 目录复制，全部完成后再替换工作目录。首次复制被中断不再污染正式目录，也不需要人工删除。
- 缓存校验扩展为检查全部必要文件，缺失任一组件会重新准备。
- 便携版 EXE 使用每次启动独立的解压目录。此前多次启动同一 EXE 会复用一个固定的临时目录，后启动的实例会清空先启动实例正在使用的 OBS 运行时文件，用户会看到"内置 OBS Runtime 不可用"并在检查列表中列出整组缺失文件。

### 发布流程

- Release workflow 增加内置 OBS 包校验、便携版重复启动校验和采集引擎切换校验。

## 未包含在本版中的改动

本版不改变网络或采集架构：仍为 P2P 优先，VDO.Ninja direct fallback，TURN 只在直连竞速耗尽后作为 relay-only 兜底；OBS 固定帧率采集与 Electron 原生采集行为不变。

## 已知限制

- 当前版本未进行商业代码签名，Windows SmartScreen 可能提示未知发布者。
- 观看者和房主都需要安装 Roomcast，当前没有浏览器免安装观看入口。
- 未配置 PEER_SERVER_URL 时，PeerJS 公共信令服务可能处理连接元数据。
- VDO.Ninja direct fallback 依赖其公共服务；TURN 需要自行部署或配置。
- 房间服务和聊天数据为内存态，房间关闭后不保留历史。
- macOS / Linux 暂不在本发布线支持范围内。
- **OBS 偶发清理失败的本版修复针对已由 OBS 32.1.2 源码确认的机制（延迟销毁的来源仍被枚举）。本版尚未在真实 OBS 采集压力循环下完成闭环复验；如仍偶发出现"OBS 临时枚举源无法清理"，请附上操作顺序和 OBS 日志反馈。**
- **首次入房的截止时间修复已由单元测试和源码级校验覆盖，尚未在跨机 / 真实 NAT 环境完成双端首连闭环验证。**
- 更完整的未验证项见 docs/STATUS.md。

## 升级说明

- 直接替换旧版本程序目录或便携 EXE 即可。
- 设置保存在 Electron 用户数据目录，版本升级使用原有迁移逻辑。
- 邀请链接格式保持 roomcast://join/... 格式。
- 房间成员在迁移或高级功能前，建议统一更新到最新 Beta 版本。
