# 自动更新实现与验证

当前本地修复版本：0.14.4-beta.7。

## 对照的开源实现

- [electron-builder v26 自动更新支持范围](https://www.electron.build/v26/docs/features/auto-update/)：Windows 标准更新目标是 NSIS 安装版，不能直接把现有单 EXE 便携包交给 NsisUpdater。
- [electron-updater BaseUpdater](https://github.com/electron-userland/electron-builder/blob/v26.0.12/packages/electron-updater/src/BaseUpdater.ts)：安装入口防重复执行，校验下载后交给独立安装进程，随后退出应用。
- [VS Code Windows 更新服务](https://github.com/microsoft/vscode/blob/main/src/vs/platform/update/electron-main/updateService.win32.ts)：下载、准备、安装和重启有明确的状态边界。
- [Velopack Windows 应用更新](https://github.com/velopack/velopack/blob/develop/src/bins/src/commands/apply_windows_impl.rs)：完整暂存、旧目录备份、目录切换；已移除原地 robocopy 回退。

保留现有 EXE/ZIP 分发格式。借鉴上述生命周期和事务设计，不引入要求更换分发格式的框架，也未复制其实现代码。

## 当前流程

1. 固定发布信息快照；更新入口在异步操作前防止重复进入。
2. 下载至临时文件，校验发布页 SHA256；准备安装时再复核落盘文件。
3. 生成 JSON 事务计划和独立 Windows 更新工作程序。目录版检查必要文件，并生成物理文件哈希清单；Electron 内使用 original-fs 处理真实 app.asar。
4. 原生 GUI 启动器用 CreateProcess 的 BREAKAWAY_FROM_JOB 和 NO_WINDOW 标志交接工作程序，不继承标准管道句柄。主应用收到真实启动记录后才退出。
5. 工作程序独占目标更新锁，等待旧主进程；便携版仅在父进程确为该便携启动器时等待父进程。
6. EXE 在目标同目录完整暂存后用 File.Replace 原子替换；目录版完整暂存并保留用户额外文件，备份旧目录后切换新目录。移除了旧 CMD/tasklist/copy/robocopy 安装路径。
7. 新主程序确认 React 主界面与桌面桥已就绪，写实际版本和随机事务令牌回执。收到相符回执后记录 COMMITTED。启动失败、版本不符或无回执时恢复旧版。
8. 自动回滚只停止由本事务启动的新程序。旧版备份保留；失败或未提交日志保留，自动清理仅处理一天前的已提交工作目录。

## 验证入口

- `npm test`：更新下载、校验、计划、回执、归档解析与现有应用回归。
- `npm run check:update-apply`：隔离的真实 Windows 文件/进程测试，覆盖运行映像占用、下载篡改、启动失败、版本不符、目录切换和目录回滚。
- `node scripts/check-packaged-update.cjs`：使用本地 beta.6 副本升级至本地 beta.7 包，验证真实 NSIS 启动器退出和新主界面回执，不下载网络发布包。

## 迁移与边界

已经安装的 beta.2 在首次更新时仍执行其旧更新程序；下载新版 EXE 不会先替换旧更新逻辑。因此首次应关闭旧版后使用完整 beta.7 包。后续更新使用新的事务程序。

用户日志只证明替换阶段连续“拒绝访问”，不能区分用户机器上的映像占用、目录权限或安全软件限制。本机复现证明直接覆盖运行映像会失败，另发现旧进程查询/交接策略不可靠。断电、系统强制终止和用户机器的安全策略不在自动化验证证明范围内。
