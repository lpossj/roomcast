# 自动更新实现与验证

当前修复版本：0.14.4-beta.8（2026-10-02 同版本修订）。

## 对照的开源实现

- [electron-builder v26 自动更新支持范围](https://www.electron.build/v26/docs/features/auto-update/)：Windows 标准更新目标是 NSIS 安装版，不能直接把现有单 EXE 便携包交给 NsisUpdater。
- [electron-updater BaseUpdater](https://github.com/electron-userland/electron-builder/blob/v26.0.12/packages/electron-updater/src/BaseUpdater.ts)：安装入口防重复执行，校验下载后交给独立安装进程，随后退出应用。
- [VS Code Windows 更新服务](https://github.com/microsoft/vscode/blob/main/src/vs/platform/update/electron-main/updateService.win32.ts)：下载、准备、安装和重启有明确的状态边界。
- [Velopack Windows 应用更新](https://github.com/velopack/velopack/blob/92d6a1c91716729d449034df5c50307dcce39493/src/bins/src/commands/apply_windows_impl.rs)：完整暂存、旧目录备份、目录切换；已移除原地 robocopy 回退。
- [Electron ASAR 文件系统](https://www.electronjs.org/docs/latest/tutorial/asar-archives)：普通 Node fs 支持读取归档内文件，original-fs 直接处理物理归档，不解析归档内部路径。

保留现有 EXE/ZIP 分发格式。借鉴上述生命周期和事务设计，不引入要求更换分发格式的框架，也未复制其实现代码。

本轮实际克隆 electron-builder v26.0.12（44c5265a9260ca6f319f111b5a2ca7e50b0a7cd6）和 Velopack（92d6a1c91716729d449034df5c50307dcce39493），核对安装交接与目录切换源码。参考副本仅存放在本地 .test/references，不进入程序包。

## 当前流程

1. 固定发布信息快照；更新入口在异步操作前防止重复进入。
2. 下载至临时文件，校验发布页 SHA256；准备安装时再复核落盘文件。
3. 生成 JSON 事务计划；复制 resources/runtime/update-launcher 内的原生更新程序到独立临时目录。目录版检查必要文件，并生成物理文件哈希清单；Electron 内使用 original-fs 处理载荷的真实 app.asar。更新不再读取或生成归档内 PowerShell 脚本。
4. 原生 GUI 程序直接用 Windows/.NET 文件与进程接口执行完整事务。优先用 CreateProcess 的 BREAKAWAY_FROM_JOB 标志启动独立自身进程；外层长期运行的宿主 Job 拒绝该标志（Windows 错误5）时，记录原因并普通原生创建，保留旧进程退出后才替换的保护，不继承标准管道句柄。不调用 PowerShell、CMD、执行策略绕过或编码命令。主应用收到真实启动记录后才退出。外层宿主终止整个 Job 属于强制进程终止边界。
5. 工作程序独占目标更新锁，等待旧主进程；便携版仅在父进程确为该便携启动器时等待父进程。
6. EXE 在目标同目录完整暂存后用 File.Replace 原子替换；目录版完整暂存并保留用户额外文件，备份旧目录后切换新目录。移除了旧 CMD/tasklist/copy/robocopy 安装路径。
7. 新主程序确认 React 主界面与桌面桥已就绪，写实际版本和随机事务令牌回执。收到相符回执后记录 COMMITTED。启动失败、版本不符或无回执时恢复旧版。
8. 新应用暂停创建后加入独立 Windows Job，再恢复运行；自动回滚只结束该 Job 内本次启动的新程序树。提交时解除随更新程序退出的终止条件，并允许后续更新独立交接，避免第一次更新成功但下一次被进程 Job 限制。旧版备份保留；失败或未提交日志保留，自动清理仅处理一天前的已提交工作目录。Windows Job 生命周期按 [Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)核对。

## 验证入口

- `npm test`：更新下载、校验、计划、回执、归档解析与现有应用回归。
- `npm run check:update-apply`：隔离的真实 Windows 文件/进程测试，覆盖运行映像占用、下载篡改、启动失败、版本不符、目录切换、目录回滚和连续两次原生更新。
- `node scripts/check-update-job.cjs`：把相同真实事务放入禁止脱离的 Windows Job，确认错误5兼容路径被执行及交接/回滚/连续更新。
- `node scripts/check-update-asar.cjs [最终成品app.asar路径]`：由 Electron 从真实 ASAR 内加载安装器，检查外置原生 worker 完整复制、目录载荷物理清单和不生成脚本；不从工作区导入安装器。
- `node scripts/check-packaged-update.cjs <成品目录> [--directory]`：从新成品的真实 ASAR 加载安装器，替换隔离的本地 beta.7 EXE 或目录副本，验证旧进程退出、新主界面就绪和版本回执，不下载网络发布包。该检查使用修订后的安装器，不能证明旧 beta.7 更新器能自行完成首次升级。

## 迁移与边界

beta.7 和首次发布的 beta.8 存在包内脚本读取错误：original-fs 不能打开 app.asar/electron/update-worker.ps1，因此安装准备阶段报 ENOENT。安装文件夹名称不能代表实际版本，用户截图目录名虽为 beta.2，归档内版本实际为 beta.7。

已安装旧版仍执行它自己的更新器；新包无法在安装准备失败前替换旧逻辑。这次应关闭旧版后手动使用完整的修订 beta.8 包。ZIP 版换到新目录，单 EXE 版替换旧启动文件；偏好保存在独立用户配置中。已安装首版 beta.8 同样需要重新下载，因为同号修订不会被更高版本检查发现。

本轮回归已先从归档内真实复现 ENOENT，再验证修复。此前成品更新检查从工作区加载安装器，只证明事务和新界面确认，未覆盖此包内读取路径，不能作为旧版自动更新成功的证据。

用户随后提供火绒“利用 PowerShell 执行可疑脚本”提示；只修 ASAR 读取的中间包也在真实更新交接检查中被拦截，未发布。最终改为原生事务程序并删除更新脚本。未修改安全软件配置；该提示对应的 PowerShell 执行链已移除，尚不能据此承诺所有安全软件版本和策略均无其他提示。

用户日志只证明替换阶段连续“拒绝访问”，不能区分用户机器上的映像占用、目录权限或安全软件限制。本机复现证明直接覆盖运行映像会失败，另发现旧进程查询/交接策略不可靠。断电、系统强制终止和用户机器的安全策略不在自动化验证证明范围内。
