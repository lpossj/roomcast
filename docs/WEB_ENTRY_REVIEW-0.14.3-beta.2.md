# 0.14.3-beta.2 网页入口修改复核

本轮复核范围是固定网页入口及其发布、邀请生成、页面资源路径和安全边界，不是整个软件的安全认证。

## 修改与依据

原入口需要房主进程创建 Quick Tunnel。当前网络下域名申请成功，但 QUIC 与强制 HTTP/2 的边缘连接都超时。新入口由固定 HTTPS 静态站点提供，分享弹窗只在本地生成邀请，不创建服务器或隧道进程。因此原先的 45 秒隧道创建失败路径已从默认入口中移除。

核心实现变动限制在网页入口管理、主进程入口配置、分享弹窗、静态资源相对路径和网页安全策略。P2P、VDO、TURN、房间规则、OBS、原生采集和 Windows 音频代码保持原有实现。

## 已验证的安全边界

- 原主进程 IPC 的窗口、主框架及受信任来源校验保留；网页不能调用桌面入口 IPC。
- 站点只上传 8 个公开构建文件，不上传环境配置、桌面 API、服务器模块、房间数据或长期密钥。
- 邀请密钥保留在 URL 片段中；会话存储可用时，网页读取后从地址栏移除。真实 Chrome 实测 HTTP 请求和 Referrer 不包含测试邀请密钥。浏览器禁用会话存储时，当前实现不会执行地址栏清理，仍需加固。
- 固定站点的地址本身不授予入房权限，完整邀请仍需通过原有高熵密钥认证。
- CSP meta 阻止内联脚本；页面拒绝在 iframe 中渲染房间控件。GitHub Pages 不支持任意安全响应头，这里没有把 meta 误当成 frame-ancestors 响应头。
- 桌面本地服务继续监听 loopback，站点不反向代理本机服务。
- 默认观看地址不包含账号、密码、查询、片段或非标准端口；受信任环境配置的自定义入口也执行该校验。
- Windows 包的最小 Electron fuses、ASAR 完整性及运行时 SHA256 校验保持原有设置。

## 已验证的可用性

- 166 项测试、构建、许可证与网络架构检查通过。
- 子目录网页能加载资源、解析邀请，网页再次分享保留部署路径。
- 线上文件逐项 SHA256 与本地审查构建一致，HTTPS 已开启。
- 便携 EXE 启动、版本及资源校验通过。
- 同一台 Windows 机器上的新便携 EXE 房主与实际线上 Chrome 网页访客完成入房、聊天和再次分享；链接生成约 1 秒。
- 网页发布采用独立 gh-pages 分支。后续更新必须保留此前使用内容哈希命名的资源，避免缓存 HTML 或已有标签页加载不到旧模块。

## 尚不能保证的部分

固定站点消除了每次启动隧道的依赖，但仍依赖使用者能访问网页域名、信令及相应媒体服务。没有验证所有地区、运营商、VPN、手机浏览器、长时间运行及弱网组合，不能宣称任何网络下都稳定。

托管仓库账号及静态发布分支属于网页代码的信任边界，应保持账号和发布权限安全；邀请应只发送给预期成员。本次没有引入用户注册或登录流程。发布前只读复核发现 gh-pages 分支尚未设置保护；邀请会保留于当前标签页会话，离房时未主动清理。这些加固尚未包含在本版中，不能把 HTTPS 或固定域名解释为完整安全保证。

没有重新实测屏幕采集、媒体播放或同步全矩阵，因为本次未修改这些实现；不能把入口及聊天验证扩大解释为完整媒体验收。Windows 产物继续保持原有未签名状态。
