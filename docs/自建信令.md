# 自建 PeerJS 信令服务

Roomcast 的远程 P2P 房间控制默认使用 PeerJS 公共信令服务。未配置时，连接元数据由第三方公共服务器处理。

如果你希望降低对公共服务的依赖，可以自建 PeerJS Server，并设置：

```text
PEER_SERVER_URL=https://signal.example.com
```

## 影响范围

- PeerJS 只负责交换 P2P 连接元数据和 ICE 信息，不承载屏幕媒体或聊天内容。
- 屏幕媒体通过 WebRTC DTLS-SRTP 传输。
- 聊天和图片通过已建立的数据通道传输，不会存入 PeerJS Server。
- PeerJS Server 仍可能看到房间 ID、IP、时间、连接数量等连接元数据。

## Docker 示例

```sh
docker run -d --name roomcast-peer \
  -p 9000:9000 \
  peerjs/peerjs-server
```

然后使用 HTTPS 反向代理：

```text
https://signal.example.com -> http://127.0.0.1:9000
```

Roomcast 的 PeerJS 配置会从 URL 中解析 host、port、secure 和 path。生产环境应始终使用 HTTPS。

## 配置位置

开发或自托管环境可以在项目根目录创建 `.env`：

```text
PEER_SERVER_URL=https://signal.example.com
```

桌面客户端当前主要面向开发和自托管构建读取该配置。后续可以在设置页中加入信令服务器配置入口。

## 默认公共服务

未设置 PEER_SERVER_URL 时：

- PeerJS 使用其默认公共云信令。
- VDO fallback 使用 wss://wss.vdo.ninja。
- TURN 只有在你配置后才使用。

如果公网服务不可用，P2P 直连可能失败。对于受限网络，建议同时自建 PeerJS 和 TURN。

## 安全建议

- 只使用 HTTPS。
- 不要公开长期 TURN access key。
- 不要把邀请链接、聊天内容或屏幕媒体发送给无关第三方。
- 自建信令服务也要限制访问来源、日志保留和资源使用。
