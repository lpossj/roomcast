# 本轮源码修改说明

范围：原生低帧率风险、局部模块拆分、主题切换效果兼容、删除测试与验收工具。未构建、测试、提交、同步或发布；运行结果由维护者自行验收。

## 原生 1 FPS：发现与修改

旧代码在源视频出现新帧时重绘 Canvas，另一个计时器只调用 requestFrame。Canvas 输出依赖请求和绘制配合，源采集压低静态画面更新或回调受阻时，计时器不必然得到预期帧数。[Canvas 采集规范](https://w3c.github.io/mediacapture-fromelement/) 是此项修改依据。

现在每个帧率周期都请求并绘制最新源画面；发生停顿后恢复正常节奏，不突发补发旧帧。默认画布按请求质量缩小、保持比例且不放大，避免 1080p 共享先反复绘制完整 4K 画布。采集结束或绘制失败时，输出轨道通知既有共享生命周期结束，并清理计时器、轨道和混音资源；混音音量控制也随输出流保留。

另一处风险是 P2P 策略原本偏向保分辨率，已有 CPU 保护主要降低高帧率上限。现在只有连续采样同时出现极低编码帧率与 CPU 限制/高编码耗时，才主动降低分辨率并暂时保帧率；健康后逐步恢复。“低帧率”或“无丢包”单独都不触发这项 CPU 判断。流畅优先设置也传递给发送端。

这是针对源码可见风险的修正，没有那次异常的运行轨迹，不能断言当时一定是 Canvas 或 CPU 原因；采集驱动、GPU、后台节流、接收端渲染等仍是未知。现有 TURN 取用与网络流程未改变。

## 彩带、声音与展开动画

- 彩带 Canvas 在 View Transition 快照层出现后创建，可能被快照遮挡。现在在快照结束后显示，并提供 100vh 尺寸回退。
- 展开效果不再依赖自定义 CSS 属性插值，改用 clip-path 圆形动画；缺少 View Transition 或伪元素动画能力时，使用普通 DOM/CSS 圆形涟漪。回退效果是主题切换后的涟漪，并不等同于支持设备上的完整新旧页面快照展开。
- 提示音在点击处理的同步阶段请求 AudioContext 恢复，再播放；增加 webkitAudioContext 兼容和已关闭上下文重建，避免尚未 resume 完成就排入声音。
- 系统“减少动态效果”仍有意跳过彩带和展开；页面隐藏、尺寸变化会取消动效。系统静音、浏览器策略、实际设备性能问题不能仅由源码确定，本轮不声称已在对应设备证明恢复。
