# Roomcast 0.14.4-beta.10（本地人工验收版）

本轮以 2026-10-13 本地 beta.9 为基线，保留此前 EasyTier 集成、UDP 优先尝试、画质恢复与分阶段超时修改。GitHub 仅作参考，没有拉取旧源码覆盖本地。

## 本轮改动与源码依据

- `src/ScreenPlayer.jsx`：远端播放初始化原先每次执行 `setSound(false)`，覆盖 `initialSound` 以及用户已开启的声音。现在连接重建保留声音选择；本机预览仍静音，主动静音与音量仍由用户控制。
- `src/room-voice.js`：已连通语音若持续处于 `disconnected`，原先不会被既有重试循环替换。现在复用屏幕连接的 8 秒宽限，只移除该条持续断线连接，由既有 5 秒循环重试。恢复、退出、移除时清理计时器和事件；初次连接仍使用 20 秒期限。这里的时间是代码期限，不是实测恢复耗时。
- `src/ScreenPlayer.jsx`：凭据轮换处理缺少 EasyTier 回退状态判断，会让正常或正在准备的备用观看连接重新跑直连。现在与现有 TURN 分支一样保留该连接；VDO 仍按原机制更新，成员移除与鉴权保持原有处理。
- `src/ScreenPlayer.jsx`：自适应播放缓冲改用同一入站统计对象相邻采样的解码耗时，避免全会话平均长期保留旧负载。继续使用原 35–200ms 边界和平滑逻辑；缺项、计数重置、无新增帧不当作有效解码测量。
- `package.json`、`package-lock.json`：同步到 `0.14.4-beta.10`，未调整依赖。

没有修改 Worker、公网 TURN 功能/凭据获取/启用规则，没有新增中继不可用提示，没有修改系统代理、DNS、默认路由或开放管理接口。未增删测试。OBS、原生采集、系统声音、语音和网页入口保留。

## 证据范围与未确认事项

本轮只做源码审查和正常构建打包，未编写或运行自动化测试、烟雾测试、验证脚本，也未运行客户端。构建状态以本轮时间戳收尾为准，不能当成功能验收。

实际入房成功率、首帧耗时、画质回升、声音连续性、浏览器自动播放及校园网效果尚未确认。此前 300–600ms 缺少同一会话的控制 RTT、媒体收发统计及 EasyTier 底层线路信息，不能归因或承诺降幅。未据此调整节点、MTU、核心队列或重复添加画质控制器。公共信令/节点的线路与长期可用性仍是外部条件。

参考定义：[WebRTC 连接状态](https://www.w3.org/TR/webrtc/#dom-rtcpeerconnectionstate)、[解码统计累计量](https://www.w3.org/TR/webrtc-stats/#dom-rtcinboundrtpstreamstats-totaldecodetime)。这些是机制依据，不是 Roomcast 实测。

## 人工验收（最多 5 项）

1. 两台 Windows 电脑在常用网络与校园网分别创建/加入房间、点击观看，记录入房/首帧耗时及显示路线；有第三名正常观看者时确认失败成员不会打断他。
2. 播放含声音的视频，开启共享声音后点重新连接，确认恢复后声音选择和音量保持；主动静音后重连也应继续静音。分别用 OBS 和原生采集留意音画同步、应用声音选择/排除。
3. 两人语音保持一段时间后，在房间仍在线的前提下让语音短暂断线并恢复，确认自动恢复且无重复声音；之后关闭麦克风、移除成员、退出房间，确认不会重新发声。
4. 三人房间中一人经 EasyTier 看画面，房主移除另一人触发凭据轮换；确认保留成员画面/声音继续，被移除成员仍失去访问。若有 VDO 观看者，确认其能按原机制重新连接。
5. 高运动画面与静态文字交替播放，网络/解码负载恢复后观察清晰度、帧率及延迟是否恢复；电脑/手机网页用新静态包另行验收观看、声音按钮和返回前台。线上旧站点不代表本地 beta.10。
