## 2026-09-26 23:30:04 +08:00 — 定位到三个代码缺口与线上版本

- 邀请：src/App.jsx仅模块启动读取search/hash，随后清除fragment；没有hashchange/popstate监听。浏览器在同一文档导航到新fragment不会重启模块，因此新邀请不能重新弹加入UI。已定位可复现实验路径，尚未宣称每一种手机失败原因均相同。
- 幽灵成员：P2PRoom.accept为每个已认证网页成员建立房主本地Socket.IO桥接，cleanup仅在Peer close/error触发时断开桥接。手机WebView关闭/冻结而没有及时上报close时，该本地桥接还在，server会把成员保留。现有代码没有房间级成员存活定时核对。
- 退出：handleLeave第一次调用leave(false)，仍等待迁移；只有connection=leaving时第二次才强制。与用户“第一次就退出”的要求不符，必须改成直接leave(true)，移除第二次点击入口。
- 原生Windows X/Alt+F4已经直接process.reallyExit，保持该已实测入口，不增加新按钮。
- 浏览工具访问公开网页失败；改用HTTP只读取得index及683935字符的bundle，确认线上index-D7bwsBp3.js内版本0.14.3-beta.3，不是本次桌面beta.6。GitHub Pages来源为gh-pages根目录，build_type=legacy。证据保存.test/mobile-live-index-20260926.html与mobile-live-bundle-20260926.js。
- 方案：监听同文档邀请变化，只预填并显示加入确认，不自动入房；房主定时使用旧beta.3已经支持的只读migration:probe检查响应，超时只清理该成员桥接/连接，避免要求旧网页先支持新协议。探测返回ok=false也代表页面活着，不触发移交。
- 不改TURN、ICE、邀请secret或媒体车道，不下载发布包；真机微信是否遗漏关页事件尚属推断，将通过模拟“不发close、没有响应”的回归验证。
