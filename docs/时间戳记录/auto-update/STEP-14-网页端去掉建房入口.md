# STEP-14 网页端去掉"创建房间"入口（只保留加入观看 + 浏览器共享）

> 时间：创建于 2026-09-26 16:44；本步的完整时间线见 [TIMELINE-全程时间戳记录.md](TIMELINE-全程时间戳记录.md)。

- 触发：用户说明「我们一般只用邀请链接打开网页，而不是用网页包建房……网页端和手机浏览器连网页都不需要建房，
  这两个端只负责进入链接观看，然后电脑的网页端浏览器有条件就能共享」
- 决策：**去掉网页端的建房入口**；加入/观看与"电脑浏览器在房间里共享"保持不变；建房只由桌面客户端发起。
- 发布安排：随下一个版本（0.14.3-beta.3 已在构建中，不含本改动），并**重新发布一次站点**（网页端行为由站点内容决定）。

## 1. 现状与目标

| 角色 | 改前 | 改后 |
| --- | --- | --- |
| 桌面客户端 | 建房（房主）+ 共享 + 观看 | **不变** |
| 电脑浏览器（网页端） | 可用邀请链接加入观看；**也能建房（页面自己充当房间服务）**；有条件可共享屏幕 | 加入观看 + 房间内共享（`getDisplayMedia` 可用时）；**不能再建房** |
| 手机浏览器 | 加入观看（共享按钮显示"仅支持观看"） | **不变** |

## 2. 改动（`src/App.jsx`，共 8 处）

| 位置 | 改动 |
| --- | --- |
| 能力标记 | 新增 `const canHostRoom = desktopChrome;`（建房只属于桌面端） |
| 空屏入口 | `onCreate` 仅在 `canHostRoom` 时传入 → 网页端不再渲染「创建房间」按钮 |
| 左侧图标栏 | 房间按钮与「+」按钮：网页端改为打开「加入房间」，标题也相应改为"加入房间" |
| 频道侧栏 | 「开始你的房间」在网页端改为「加入房间」，点击打开加入弹窗 |
| 分享按钮 | 未入房时：桌面端打开建房、网页端打开加入（原来固定打开建房） |
| 入口弹窗 | `EntryModal` 新增 `canHost` 参数：网页端**隐藏"创建/加入"切换**，`kind` 强制为 `join` |
| 提交入口 | `handleEnter` 增加硬校验：网页端 `mode === 'create'` 直接拒绝并提示"请在电脑上用 Roomcast 客户端创建房间" |
| 旧提示 | 删除"网页建房由本页面充当房间服务……"的提示（该路径已不可达） |

**保留不变**：桌面端建房全流程；网页端用邀请链接加入、观看、聊天、再次分享；
电脑浏览器在房间内共享屏幕（`canShareScreen`）；底层"网页房间服务"实现保留但入口不可达
（网页**加入** P2P 房间仍依赖同一套房间协议，删底层风险远大于收益）。

## 3. 站点必须重新发布（本次一并执行）

网页端的行为由**站点内容**决定，而站点在 STEP-13 已冻结，所以本次改动要生效必须重新发布一次：

- 用当前 `dist/` 覆盖式合并到 `gh-pages`（**保留历史内容哈希资源**，避免已打开的标签页加载不到旧模块）；
- 写入 `version.json`（`{"version":"<当前 package.json 版本>","peerAuthProtocol":2}`）
  → 顺带把 STEP-12 里"限流降级停留在 beta.2"的问题一并解决；
- 站点不发布桌面的进度窗口页面（`updater.html` / `updater.js` 在网页里无作用）。
