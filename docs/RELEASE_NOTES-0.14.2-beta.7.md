# Roomcast 0.14.2-beta.7

本版是 0.14.2 的公开测试版（Beta），也是首个把"电脑／手机网页观看入口"完整交付的版本。0.14.2-beta.3 至 beta.6 未单独发布，迭代记录见同目录下对应的发布说明。

## 主要变化

### 网页观看入口（桌面端自动创建）

- 桌面应用打开"分享房间"时会自动用随包内置的 cloudflared 2026.9.2 建立 Cloudflare Quick Tunnel，生成电脑／手机浏览器可直接打开的 HTTPS 观看链接；离开房间或退出应用后入口关闭。
- 网页入口只提供打包后的静态页面：只接受 `GET`/`HEAD`，只服务构建产物白名单，不开放桌面本地 API、Socket.IO、音频捕获或管理接口。
- 邀请密钥放在 URL 片段中，不随请求发送给 Cloudflare；读取后从地址栏移除，并保留在当前标签页会话里以支持刷新。
- 内置 cloudflared 的官方 Windows amd64 二进制在下载、打包和发布校验三处固定同一 SHA256。

### 浏览器端房间

- 电脑和手机浏览器都能创建和加入 P2P 房间，浏览器内运行与桌面端相同的房间规则（同一份 `server/rooms.mjs`），不依赖桌面本地 API。
- 手机浏览器通常不实现 `getDisplayMedia`，因此以观看和聊天为主：共享按钮显示为"仅支持观看"，不再提供必然失败的操作。
- 电脑浏览器在支持屏幕采集且获得房间分享权限时可以发起共享。
- 网页端不再渲染只能由桌面应用提供的"窗口模式"小窗按钮。
- 网页端设置不再请求桌面配置接口；本地服务状态只在桌面端显示；图片复制和下载改用浏览器能力。
- 网页建房由该标签页充当房间服务，建房后会提示需要保持页面运行。

### 邀请链接

- 自建 PeerJS 信令地址随邀请传递（`signal` 参数），任何成员重新分享都会保留；未配置时沿用公共信令。
- beta.2 及更早版本生成的邀请不带 `signal`，配置了自建信令时可能连不上；重新生成邀请即可。

### 桌面端修复

- 桌面端不再渲染手机成员栏按钮和关闭按钮（此前会出现在宽屏布局里）。
- 共享小窗默认不置顶，控制栏可切换"置顶小窗／取消置顶"。
- 通过邀请链接进入时，浏览器禁用存储不再导致整页白屏。

## 验证

- 全量单元测试 **154/154** 通过；在**干净检出（无 `dist/`）**下同样通过。
- 新增浏览器运行时回归测试：浏览器房间服务走通共用房间规则、浏览器加密垫片与 Node `crypto` 结果逐字节一致（含 scrypt 密码房）、vite 向浏览器改写 `server/rooms.mjs` 必须命中（未命中的话构建直接失败，不再静默打包 `node:crypto`）。
- 真实浏览器（Chrome）验证：桌面宽度下两个手机成员控件为 `display: none`，手机宽度（390px）下正常显示；移除 `getDisplayMedia` 后共享按钮为禁用的"仅支持观看"；无 Electron 桥时页面可正常启动且无 pageerror。
- `vite build`、`check:licenses`、`check:network` 通过；`check:network` 不再把 `cloudflared` 当作运行时残留，改为"媒体路径不得引用临时网页入口"加"网页入口必须显式打包、版本与 SHA256 固定"。
- `verify:release` 增加对 `runtime/web-invite/cloudflared.exe` 的存在与 SHA256 校验。

## 构建工具

- 新增 `scripts/clean-build-scratch.mjs`：清理被中断的打包在 `%TEMP%` 里遗留的 `ns*.tmp` 工作目录（每个约 0.5–1.2 GB）。默认干跑，`--apply` 才删除；护栏包括名称、内容、60 分钟时效，以及"目录改名探测"——便携版运行时的解压目录与打包暂存目录形状相同，改名失败即判定为正在使用并原样保留。`beforePack` 会在每次打包前自动清理一次。

## 已知限制

- 手机浏览器能否共享手机屏幕取决于浏览器是否实现 `getDisplayMedia`；当前常见手机浏览器通常不提供该接口。需要可靠分享整部手机屏幕时，应使用支持系统屏幕录制权限的原生手机应用。
- 网页入口基于 Cloudflare Quick Tunnel（Cloudflare 将其定位为测试和开发用途，地址可能变化，有 200 并发请求限制），分享者需要保持桌面应用或网页标签页运行。
- 手机浏览器在后台会暂停 WebRTC 和视频播放，返回前台后会尝试恢复；不同内核仍需实机确认。
- 未配置自建信令时，PeerJS 公共信令服务可能处理连接元数据；VDO.Ninja fallback 依赖其公共服务；TURN 需要自行配置。
- 房间和聊天数据为内存态，房间关闭后不保留（本版按设计不引入本地数据库）。
- 其他未验证项见 `docs/STATUS.md` 与 `docs/RELEASE_CHECKLIST-0.14.2-beta.7.md`。
