# Roomcast 0.14.2-beta.6

> 说明：本版未单独发布，并入 `0.14.2-beta.7` 发布。实际交付内容以 docs/RELEASE_NOTES-0.14.2-beta.7.md 为准。

## 本版修正

- 修复桌面端误显示手机成员栏按钮和关闭按钮：这两个控件只在网页小屏布局渲染，桌面应用完全不渲染它们。
- 网页仅在浏览器提供屏幕采集能力时显示可用的共享操作。不支持屏幕采集的手机浏览器可建房、观看和聊天，共享按钮明确显示为"仅支持观看"。
- 网页端不再渲染只能由桌面应用提供的"窗口模式"小窗按钮，避免在浏览器里点出"无法创建桌面共享浮窗"。
- 修复非房主成员重新分享邀请时丢失自建信令地址（`signal` 参数）的问题；此前这类邀请生成的网页观看链接会退回公共 PeerJS。
- 通过邀请链接进入时不再因浏览器禁用存储而白屏。
- 临时网页入口现在也能服务构建产物里的根级资源（例如 favicon、worklet）。
- 延续 beta.5 的浏览器建房、手机成员栏和退出修复。

## 验证

- 全量单元测试 150/150 通过；新增浏览器运行时回归测试，覆盖浏览器房间服务共用同一套房间规则、浏览器加密垫片与 Node `crypto` 逐字节一致、以及 vite 向浏览器改写 `server/rooms.mjs` 时必须命中。
- 修复了单元测试对 `dist/` 的依赖：`npm run check` 的顺序是先测试后构建，此前在干净检出上必然失败。
- 真实浏览器验证：桌面宽度不渲染手机成员控件，手机宽度正常；移除 `getDisplayMedia` 后共享按钮为禁用的"仅支持观看"。

## 已知限制

- 手机网页能否共享手机屏幕取决于浏览器是否实现 `getDisplayMedia`；当前常见手机浏览器通常不提供该接口。需要可靠分享整部手机屏幕时，应使用支持系统屏幕录制权限的原生手机应用。
- 网页入口基于 Cloudflare Quick Tunnel（测试用途，地址可能变化，有并发限制），分享者需要保持应用或网页标签页运行。
- beta.2 及更早版本生成的邀请不含 `signal` 参数，配置了自建 PeerJS 信令时可能连不上；重新生成邀请即可。
