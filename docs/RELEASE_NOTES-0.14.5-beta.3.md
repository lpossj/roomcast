# Roomcast 0.14.5-beta.3

修复 OBS 窗口共享的一类白屏原因，并修正代码审查确认的两处使用问题。没有新增依赖、设置项或后台任务。

## 修改

- OBS 窗口采集明确使用已内置的 Windows Graphics Capture。原 Automatic 对部分 GPU 窗口选到 BitBlt，可能让本地预览和远端一起收到白帧；平台不支持 WGC 时仍由 OBS 自行回退。显示器采集保持原设置。
- 本地预览统计跳过不提供浏览器 getStats 的原生会话和准备中会话，避免异常中断更新；观看人数及普通 WebRTC 统计保持原逻辑。
- 多画面观看心跳额度按最多 9 路观看计算，修复共用每分钟 12 次额度导致合法心跳被拒、观看登记过期的问题。限流仍有上限。

## 本次验证

- 同一自建 D3D11 窗口：旧 Automatic/BitBlt 输出全白；修改后实际产品选源输出正确画面。实际 OBS 虚拟摄像头后链也取得正确画面。
- 原生采集未修改；按产品正常顺序请求 60 FPS 成功，原始轨和帧节奏 canvas 都取得正确画面。
- 自建窗口经实际 OBS 编码、原生媒体发送和本机浏览器接收，解码为 1920×1080；3.002 秒新增 180 帧，检查中无丢帧、丢包和错误。此为本机短检查，不代表公网或所有软件窗口的验收。
- 统计循环的原生、普通、混合等 5 类场景通过；真实房间事件模拟 9 路观看，修复后 117/117 次合法心跳成功，观看登记保持 9/9，超量请求仍被拒。

自有代码已完成静态审查，修复前已保存源码备份；本轮验证脚本和临时环境已清理。最小化、受保护或禁止捕获的窗口仍可能无画面。未签名 Windows 包沿用现有分发方式，安全软件提示由其策略决定。

## 保留问题

校园 P2P、EasyTier、TURN 与媒体路由本轮均未修改。信令不可达、双方桌面能力、备用节点可达性和 NAT 组合仍会影响连接；未找到符合当前约束且可证更好的替代品。

代码审查另发现：通过系统 roomcast:// 链接唤起桌面时，邀请中的 campus/signal 参数可能被过滤。当前可在程序内直接粘贴完整邀请以保留参数；此项属于网络入口，按本轮只读要求保留。原生协商/取消边界及弱网、跨设备兼容性仍需各自现场证据。

本版本发布 Windows EXE、目录 ZIP 和对应源码。既有线上网页未在本轮部署。
