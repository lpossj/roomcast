# Roomcast 状态与验证边界

当前发布线：0.14.x 公开测试版（Beta）。
当前平台：Windows 10/11 x64（桌面应用）；现代桌面与手机浏览器（网页端，以观看为主）。

## 已验收

本轮已在干净 Windows 环境完成基础验收：

- 无系统安装 OBS 时可启动。
- OBS Virtual Camera 首次注册 UAC 正常。
- OBS 固定 FPS 采集正常。
- Electron / Chromium 原生采集正常。
- 系统声音捕获正常。
- 麦克风、聊天、图片功能正常。
- P2P 优先、VDO 3 秒延迟、TURN relay-only 兜底路径符合设计。
- 本机服务监听 127.0.0.1。
- 退出后无 OBS / Electron / Roomcast 残留。
- 桌面应用可在打开"分享房间"时自动创建临时 HTTPS 网页入口（Cloudflare Quick Tunnel + 随包内置的 cloudflared 2026.9.2，打包与校验均固定 SHA256），离开房间或退出应用后关闭。

自动化层面已覆盖（`npm run check`）：

- 网页入口只服务 Vite 构建产物；桌面 API、Socket.IO、服务器模块、路径穿越和写请求一律拒绝。
- 浏览器端与桌面端共用同一套房间规则（`server/rooms.mjs`），浏览器加密垫片与 Node `crypto` 结果逐字节一致（含 scrypt 密码房路径）。
- 非房主成员重新分享邀请时会携带自建信令地址（邀请中的 `signal` 参数）。
- 打包后的 `runtime/web-invite/cloudflared.exe` 会被 `verify:release` 校验存在与 SHA256。
- 真实浏览器（0.14.2-beta.8）实测：被挂起的访客页面不再阻止房主退出（房主 1.03 秒退出并提示房间已关闭）；网页端页面后台停留 30 秒后自动退房；4000×3000 照片暂存后缩放为 2000×1500，页面不再出现可滚动溢出；不提供 `getDisplayMedia` 的浏览器不再渲染共享入口。
- 更新机制（0.14.2-beta.9）：版本比较与发布选择有单元测试覆盖（忽略 draft 与非语义化 tag、正式版不推送测试版）；对真实仓库验证过版本提示；下载路径用线上 release 的真实资产与真实 `SHA256.txt` 跑通校验；打包后的便携版验证过"检查更新"与失败兜底 UI。

详细检查表见 docs/RELEASE_CHECKLIST-0.14.2-beta.9.md。

## 尚未充分验证

下列项目不代表当前版本不可用，只表示还没有足够广泛的证据：

- 不同公网 NAT、IPv6、VPN、Tailscale 和全 UDP 封锁组合。
- 长时间运行、弱网抖动、丢包恢复和 CPU/GPU 高负载。
- 多房间同时使用 SFU / TURN 的容量和恢复。
- 手机浏览器真机观看：不同内核（iOS Safari、Android Chrome、微信内置浏览器）的后台挂起、锁屏与返回前台恢复行为。
- 手机浏览器屏幕采集。`getDisplayMedia` 在移动端普遍没有实现，因此网页端手机只能观看和聊天，共享按钮显示为"仅支持观看"；本版没有实现手机发起屏幕共享。
- Cloudflare Quick Tunnel 的可用性、地址变化和 200 个并发请求限制。
- 网页房主长时间保持标签页运行时的稳定性（网页建房由该页面充当房间服务）。
- 旧版本与新版本混合使用的完整兼容矩阵；beta.2 及更早版本生成的邀请不含 `signal` 参数，配了自建信令时可能连不上。
- 代码签名包在 SmartScreen 和不同 Windows 版本上的表现。
- 真实游戏音频与视频长期同步。

## 发布定位

当前适合作为公开测试版发布，不建议宣称为稳定版或正式版。发布时应明确：

- 未签名状态；
- Windows x64 桌面平台限制；网页端主要用于电脑浏览器共享与手机观看；
- 手机浏览器无法采集屏幕，只能观看和聊天；
- 网页入口基于 Cloudflare Quick Tunnel（Cloudflare 将其定位为测试和开发用途，地址可能变化，有并发限制），分享者需要保持桌面应用或网页标签页运行；
- 默认可能使用 PeerJS / VDO.Ninja 公网服务；
- TURN 需要自行配置；
- 房间和聊天数据是内存态，不写入数据库。

## 关于本地数据存储

本版**有意不引入本地数据库**（SQLite 或其他）。理由与边界：

- 排除了"让磁盘占用随使用增长"这一类风险：除了一次性的 OBS 运行时缓存（约 0.9 GB，位于用户数据目录）外，Roomcast 不在用户机器上累积任何随使用增长的数据；聊天、房间状态和图片都只存在于内存与会话内 ObjectURL。
- 实时成员状态依赖连接与心跳、画面依赖 WebRTC，数据库对这两条路径没有帮助。
- 本机数据库只能做到"这台电脑记得住"，无法实现"换设备还能看到"，后者需要中心服务而不是数据库选型。
- 如果将来要做跨会话历史，必须同时处理留存期限、一键清除、隐私说明更新和"未配置时功能正常"的验收项；图片应只存元数据并把实体放在磁盘文件或对象存储，且必须有总量上限。

因此本版继续维持"房间结束即释放"的行为，`PRIVACY.md` 中"不写入数据库"的承诺仍然成立。
